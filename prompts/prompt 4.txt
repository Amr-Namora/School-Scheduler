## Task 2 of 4 — School-scoping context + global exception handling

```
Building on Task 1:

SCHOOL-SCOPED CONTEXT:
- Implement ICurrentSchoolContext (interface already exists in
  Infrastructure), built on top of ICurrentUserContext: resolves
  SchoolId via the School.UserId == current user's id lookup, cached per
  request. This service should only ever be resolved for requests
  authenticated as the "School" role — if it's ever invoked for a
  non-School user (defensive check, on top of endpoint-level
  [Authorize(Roles = "School")]), throw clearly rather than silently
  returning something wrong.
- IMPORTANT RULE: any controller endpoint that calls an Application
  command/query with a SchoolId parameter must ALWAYS use
  ICurrentSchoolContext's resolved SchoolId — never accept SchoolId from
  the request body, query string, or route for these endpoints, even if
  the underlying command technically has a SchoolId parameter. This
  closes the gap flagged during the tenant-scoping audit (a client could
  otherwise pass a different school's id).
- Teacher-facing endpoints never use ICurrentSchoolContext at all — they
  use ICurrentUserContext's UserId directly (a teacher can work at
  multiple schools, so there's no single SchoolId to resolve for them).
  This applies to link requests and GetTeacherTimetableQuery now, and to
  the teacher "me" endpoints added in Task 3.

GLOBAL EXCEPTION HANDLING:
- Add exception-handling middleware (or an IExceptionHandler /
  UseExceptionHandler pipeline, whichever fits current .NET version
  best) that translates:
  - FluentValidation's ValidationException → 400 Bad Request with the
    validation errors in the response body
  - The "not found" InvalidOperationExceptions added throughout
    Application (the ones from the CRUD/tenant-scoping audit work) → 404
    Not Found
  - The "blocked delete due to dependents" and "capacity exceeded" /
    "teacher not assigned to subject" InvalidOperationExceptions → 409
    Conflict (or 400, your call — pick one and apply it consistently,
    tell me which)
  - Anything else unhandled → 500, but logged with enough detail to
    debug
- Don't let raw exception messages/stack traces leak to the client in
  the 500 case; do include the specific message in the 400/404/409
  cases since those are expected, meaningful errors the client should
  see.

List every file created/changed.
```
