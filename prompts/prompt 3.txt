## Task 3 of 3 — CP-SAT scheduling solver

```
Building on Tasks 1-2, implement ITimetableGenerationService using the
Google.OrTools NuGet package's CP-SAT solver.

Model each (ClassRoom, Day, Slot) as a decision variable domain over
possible (Subject, Teacher) pairs, constrained to:
1. HardConstraint: teacher not double-booked at same (Day, Slot) across
   all classes they're assigned to
2. HardConstraint: teacher only assigned within their declared
   TeacherAvailability
3. HardConstraint: sum of a subject's occurrences per class per week
   equals its WeeklyQuota exactly
4. HardConstraint: a subject appears at most 2 times per day per class
5. HardConstraint: no teacher has 3+ consecutive slots (same day) with
   no break between them — model this as a sliding window constraint
   over consecutive slot numbers

If the solver finds the problem infeasible, return a result object that
explains which constraint category likely caused it (as far as OR-Tools'
infeasibility info allows), not just "failed."

Keep the solver logic in its own well-named class(es), separate from EF
Core code, so it stays testable in isolation.

Explain briefly how you modeled the CP-SAT variables and constraints
(2-3 sentences), so I can sanity-check the approach before we move to
the API layer. List every file created/changed.
```
